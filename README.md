# 책이지 시험 이용 화면(D안)

부천시립도서관 16곳에서 책을 찾고, 누리집 상호대차 신청 화면까지 안내하는 **직원 시험 이용 화면**입니다.

- **바로 열기**: https://altarry-prog.github.io/chaekiji-pilot/
- **누구를 위한 것인가**: 상동도서관 직원이 실제 이용자로서 써 보는 비공개 시험용입니다. 주소는 초대한 분께만 알립니다.
- 판 **v0.1.0**(2026. 10. 18.) · 모의 중계 점검 66건 통과(2026. 10. 18.)

> **정직 고지** — 부천시립도서관의 공식 서비스가 아닙니다. **책이지는 신청하지 않습니다.** 신청은 이용자가 누리집에 로그인해 직접 합니다. 대출 상태는 도서관 정보나루 **전일 기준**입니다.

## 1. 무엇을 하나

1. 책 이름을 말하거나 입력합니다.
2. 책이지 상담 비서가 16개관의 소장·대출 상태를 보고 갈래를 판정합니다. 갈래는 바로 이용, 관내 상호대차, 예약 권장, 책바다 안내, 소장 확인 불가 가운데 하나입니다.
3. 「누리집에서 이 책 신청하기」를 누르면 그 책의 누리집 화면(ISBN)이 열립니다. 신청은 거기서 본인이 합니다.

화면에는 16개관을 책등 16권으로 보여 주는 선반이 있습니다. 칠한 책등은 대출 가능, 빗금은 대출 중, 점선은 없음입니다. 같은 내용을 글로도 적습니다.

## 2. 어떻게 동작하나

- **판정** — 책이지 원격 상담 비서(`altarry-prog/chaekiji` 저장소 `relay/mcp.js`의 `consult_request`)를 그대로 부릅니다. 이 화면은 판정을 새로 만들지 않고, 결과를 이용자의 말로 옮깁니다.
  - 그 엔진의 시험: 자동 시험 102건, 중계 점검 20건, 원격 점검 37건, 파이썬 판 대조 28건(2026. 10. 19. 서지 고르기 보완 뒤)
- **다른 판본** — 중계의 `/search`(정보나루 서지 검색)로 같은 제목의 다른 판본을 보여 줍니다. 다른 판본은 판정하지 않고 누리집 그 판본 화면으로 잇습니다.
- **받을 도서관** — 시립도서관 16곳과 작은도서관 8곳입니다. 작은도서관 목록은 누리집 「상호대차 신청」의 받을 곳 목록입니다(2026. 10. 18. 확인). 작은도서관의 도착일·보관 기한은 정보나루에 없어 「그 도서관에 확인」으로 안내합니다.
- **규정 문장** — 부천시립도서관 누리집 상호대차 안내(최종수정 2026. 8. 10.)에 맞췄습니다. 평일 다음 날 도착, 도착일 포함 3일 보관, 기한이 지나면 자동 반납과 7일 신청 제한입니다.

## 3. 개인정보와 기록

- 이름과 회원번호를 받지 않습니다. 보내는 것은 책 이름, 받을 도서관, 언어(ko) 셋입니다.
- 찾은 책을 기록으로 남기지 않습니다. 화면과 중계 코드 모두 검색어를 저장하지 않습니다. 중계는 같은 질문에 10분 동안 기억해 둔 답을 씁니다.
- 기기에는 고른 받을 도서관 하나만 기억합니다.
- 외부로 부르는 곳은 책이지 중계 하나입니다. 글꼴이나 분석 도구를 불러오지 않습니다.
- 말로 찾기는 쓰시는 브라우저의 음성 인식을 씁니다.
- 검색 엔진에 나오지 않게 해 두었습니다(noindex).

## 4. 시험 방법

- 상동도서관 직원 3~5명이 실제로 빌리고 싶은 책이 생겼을 때만 씁니다. 기록은 익명(직원 A~E)입니다.
- 1차는 2026. 10. 27.~11. 3., 2차는 11. 20.까지입니다(계획안 기준).
- 판정이 맞았는지는 누리집 화면(실시간)과 실제 신청·수령 결과로 확인합니다.
- 이용할 때마다 기록지에 한 줄을 적고, 책 제목은 적지 않습니다.

## 5. 점검

- **모의 중계 점검** — 갈래별 문구·링크·선반, 오류 처리, 받을 도서관 기억, 말로 찾기, 320·390·1280px 화면, 접근성(axe)을 봅니다. 중계 응답은 책이지 엔진의 출력 형태(`tests/fixtures.json`)와 2026. 10. 18. 실제 응답 4건(`tests/fixtures_real.json`)입니다.

  ```
  npm install
  node tests/check_pilot.mjs
  ```

- **실제 점검** — 깃허브 액션 `check.yml`이 게시된 화면을 실제 중계로 열어 시연 도서 2권을 찾고, 결과를 `check/last_check.json`에 남깁니다. 고칠 때마다, 그리고 매일 10:17(한국 시간)에 돕니다. 정보나루 호출은 1~2회 안팎입니다.
- **게시** — 깃허브 액션 `pages.yml`이 main에 올릴 때마다 저장소 그대로를 깃허브 페이지스에 게시합니다.

## 6. 알려진 한계

- 대출 상태는 전일 기준입니다. 오늘 대출되거나 반납된 책은 다를 수 있습니다.
- 정보나루 하루 조회 한도 500회를 매일 갱신·창구 시험과 함께 씁니다. 처음 찾는 책 한 권에 17회 안팎이 들어 하루 약 24권까지입니다(추정). 넘으면 「소장 상태를 확인하지 못했어요」로 안내합니다.
- 다른 판본은 판정하지 않습니다.
- 책바다(전국 상호대차)는 안내만 합니다.
- 판정 엔진은 `chaekiji` 저장소에 있어 2026. 11. 8. 제출 동결 뒤에는 고치지 않습니다. 이 화면은 별도 저장소라 동결과 관계없이 고칠 수 있습니다.
